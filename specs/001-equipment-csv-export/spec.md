## Clarifications

### Session 2026-09-23

- Q: 他部署への共有にも使うCSVに、貸出中の備品の借用者（社員の個人名）を含めてよいか？ → A: 含める（貸出中の備品のみ氏名を出力し、それ以外は空欄）。画面上で両ロールが既に閲覧できる情報であり、棚卸しでの所在確認に必要なため。
- Q: 値が `=`・`+`・`-`・`@` で始まる場合、どのように無害化して出力するか？ → A: 値の先頭にシングルクォート `'` を付けて出力する（例：`=SUM(A1)` → `'=SUM(A1)`）。
- Q: CSVダウンロードのURLに不正な検索条件（存在しない状態など）が指定された場合の挙動は？ → A: ダウンロードせず一覧画面へ戻し、検索条件が不正である旨のエラーメッセージを表示する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 備品一覧をCSVでダウンロードする (Priority: P1)

現場の担当者（管理者・一般ユーザーのいずれも）が、棚卸しの集計や他部署への共有のために、備品一覧画面の「CSVダウンロード」ボタンを押して、登録されている備品の情報をCSVファイルとして手元に保存する。保存したファイルは表計算ソフト（Excel）でそのまま開けて、文字化けせずに読める。

**Why this priority**: 依頼の中核そのものであり、これだけで「棚卸し時に Excel で集計する」「他部署に共有する」という要望が満たされる。

**Independent Test**: 検索条件を指定せずに備品一覧画面を開き、「CSVダウンロード」ボタンを押す。ダウンロードされたファイルを Excel で開き、画面に表示されている全備品が同じ順序・同じ内容で1行ずつ出力されていることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理者でログインし備品一覧画面を表示している, **When** 「CSVダウンロード」ボタンを押す, **Then** 画面に表示されている全備品を含むCSVファイルがダウンロードされる
2. **Given** 一般ユーザーでログインし備品一覧画面を表示している, **When** 「CSVダウンロード」ボタンを押す, **Then** 管理者と同じ内容のCSVファイルがダウンロードされる
3. **Given** ダウンロードしたCSVファイルがある, **When** Excel でダブルクリックして開く, **Then** 日本語（品名・状態など）が文字化けせずに表示され、1行目に列見出しが表示される
4. **Given** 状態が「利用可」「貸出中」「故障中」の備品が混在している, **When** CSVをダウンロードする, **Then** 状態列には画面と同じ日本語表記（「利用可」「貸出中」「故障中」）が出力される
5. **Given** 保管場所や購入日が未登録の備品がある, **When** CSVをダウンロードする, **Then** 該当セルは空欄で出力され、列がずれない

---

### User Story 2 - 検索で絞り込んだ備品だけをCSVでダウンロードする (Priority: P2)

担当者が、品名や状態で備品一覧を絞り込んだ状態（例：状態＝「故障中」のみ）で「CSVダウンロード」ボタンを押し、画面に表示されている絞り込み結果だけをCSVファイルとして保存する。

**Why this priority**: 依頼の「今画面に表示されている備品の情報を出力してほしい」に直接対応する。全件出力（P1）が動けば最低限の価値は出るため P2 とする。

**Independent Test**: 品名または状態で検索して一覧を絞り込んだ後に「CSVダウンロード」ボタンを押し、出力された行が画面に表示されている備品と完全に一致する（件数・順序・内容）ことを確認する。

**Acceptance Scenarios**:

1. **Given** 状態＝「故障中」で絞り込んだ一覧を表示している, **When** 「CSVダウンロード」ボタンを押す, **Then** 「故障中」の備品だけがCSVに出力される
2. **Given** 品名に「PC」を指定して絞り込んだ一覧を表示している, **When** 「CSVダウンロード」ボタンを押す, **Then** 品名に「PC」を含む備品だけがCSVに出力される
3. **Given** 品名と状態の両方で絞り込んだ一覧を表示している, **When** 「CSVダウンロード」ボタンを押す, **Then** 両方の条件を満たす備品だけがCSVに出力される
4. **Given** 検索条件に一致する備品が0件で一覧が空になっている, **When** 「CSVダウンロード」ボタンを押す, **Then** 列見出し行のみのCSVファイルがダウンロードされる（エラーにはならない）

---

### Edge Cases

- 品名・保管場所などにカンマ（,）、ダブルクォート（"）、改行が含まれる場合でも、Excel で開いたときに列がずれず、入力どおりの値が1セルに表示されること。
- 品名・保管場所の値が `=`、`+`、`-`、`@` で始まる場合、Excel で開いたときに数式として実行されないこと（CSVインジェクション対策）。値の先頭にシングルクォート `'` を付けて文字列として扱わせる（FR-012）。
- 備品が1件も登録されていない場合：列見出し行のみのCSVファイルがダウンロードされる。
- 未ログイン状態でCSVダウンロードのURLに直接アクセスした場合：ファイルはダウンロードされず、ログイン画面へ誘導される。
- 状態に存在しない値など、不正な検索条件でダウンロードを要求した場合：CSVはダウンロードされず、一覧画面へ戻って「検索条件が不正です」等のエラーメッセージが表示される。スタックトレースは表示しない（FR-017）。
- 同じ日に複数回ダウンロードした場合：ファイル名に日時が含まれるため、保存先で上書きされにくい。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは備品一覧画面に「CSVダウンロード」ボタンを表示しなければならない。
- **FR-002**: 「CSVダウンロード」ボタンは、管理者（ROLE_ADMIN）・一般ユーザー（ROLE_USER）の双方が利用できなければならない（備品一覧の閲覧権限と同じ）。
- **FR-003**: ボタンを押すと、システムは備品一覧データをCSVファイルとしてブラウザにダウンロード（保存）させなければならない。画面遷移は発生させず、利用者は一覧画面に留まる。
- **FR-004**: CSVに出力する備品は、ボタンを押した時点で一覧画面に適用されている検索条件（品名の部分一致、状態の完全一致）と同じ条件で抽出したものでなければならない。検索条件が未指定の場合は全備品を出力する。
- **FR-005**: CSVの行の並び順は、同じ検索条件で一覧画面に表示される順序と一致しなければならない。
- **FR-006**: CSVの1行目は列見出し行とし、列見出しは日本語で「品名」「管理番号」「保管場所」「状態」「購入日」「借用者」の順としなければならない。2行目以降は備品1件につき1行とする。
- **FR-007**: 「状態」列には画面と同じ日本語表記（「利用可」「貸出中」「故障中」）を出力しなければならない。
- **FR-008**: 「購入日」列は `yyyy-MM-dd` 形式で出力し、未登録の場合は空欄としなければならない。「保管場所」が未登録の場合も空欄としなければならない。
- **FR-009**: 「借用者」列には、状態が「貸出中」の備品について現在の借用者の氏名を出力し、それ以外の備品は空欄としなければならない。借用者名は一覧画面で両ロールが既に閲覧できる情報であり、CSVに含めても新たな情報開示にはならない。
- **FR-010**: CSVファイルは Excel で開いたときに日本語が文字化けしない文字コード（BOM付きUTF-8）で出力しなければならない。
- **FR-011**: 値にカンマ・ダブルクォート・改行が含まれる場合は、値をダブルクォートで囲み、値中のダブルクォートは二重化して出力しなければならない（一般的なCSVの規則に従う）。
- **FR-012**: 値が `=`、`+`、`-`、`@` のいずれかで始まる文字列項目（品名・管理番号・保管場所・借用者）は、表計算ソフトで数式として解釈されないよう、値の先頭にシングルクォート `'` を付けて出力しなければならない（例：`=SUM(A1)` → `'=SUM(A1)`、`-20℃用冷蔵庫` → `'-20℃用冷蔵庫`）。該当しない値は変更しない。
- **FR-013**: ダウンロードされるファイル名は `equipment_yyyyMMdd_HHmmss.csv`（ダウンロード時点の日時）としなければならない。
- **FR-014**: 未ログイン状態でのCSVダウンロード要求は拒否し、ログイン画面へリダイレクトしなければならない。
- **FR-015**: 対象の備品が0件の場合、システムは列見出し行のみのCSVファイルを出力しなければならない。
- **FR-016**: CSVの出力処理で想定外のエラーが発生した場合、システムは利用者に分かりやすいエラーメッセージを表示し、エラー内容をログに記録しなければならない。
- **FR-017**: CSVダウンロード要求の検索条件が不正な場合（状態に存在しない値が指定された場合など）、システムはCSVを出力せず、一覧画面へ戻して検索条件が不正である旨の日本語エラーメッセージを表示しなければならない。

### Key Entities *(include if feature involves data)*

- **備品（Equipment）**: 既存のエンティティ。CSVには品名・管理番号・保管場所・状態・購入日を出力する（ID・登録日時・更新日時は出力しない）。
- **貸出記録（Lending）**: 既存のエンティティ。状態が「貸出中」の備品に対応する未返却の貸出記録から、借用者（社員）の氏名を参照する。
- **CSV出力行（エクスポート行）**: 備品1件をCSVの1行として表したもの。永続化はしない、出力時にのみ組み立てる表示用のデータ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は備品一覧画面から1回のボタン操作で、画面に表示されている備品一覧のCSVファイルを入手できる。
- **SC-002**: ダウンロードしたCSVファイルを Excel でダブルクリックして開いたとき、追加の設定（文字コード指定やインポートウィザード）なしで、日本語が文字化けせずに正しい列に表示される。
- **SC-003**: CSVに出力された行の件数・順序・各列の値が、同じ検索条件で表示した一覧画面の内容と 100% 一致する。
- **SC-004**: 品名・保管場所にカンマ・ダブルクォート・改行・数式の先頭文字を含む備品があっても、Excel で開いたときに列ずれや数式実行が 0 件である。
- **SC-005**: 想定データ量（数十件程度）で、ボタンを押してからファイルの保存が始まるまで 3 秒以内である。

## Assumptions

- 依頼の「今画面に表示されている備品」は、「一覧画面に現在適用されている検索条件で絞り込まれた備品」と解釈する。
- 依頼の「使いやすい形式」は、「Excel でそのまま開ける（BOM付きUTF-8）」「日本語の列見出しあり」「状態は日本語表記」「空値は空欄」と解釈する。
- 出力列は一覧画面に表示されている項目（品名・管理番号・保管場所・状態・購入日・貸出中の借用者）に合わせる。画面上の操作用の列（貸出・返却ボタン、編集・削除ボタン）は出力しない。
- CSVダウンロードは閲覧操作であり、一覧画面の閲覧権限（ADMIN・USER）と同じ範囲で許可する。
- データは数十件程度であり、ページ分割・非同期処理・件数上限は不要（依頼の「パフォーマンスは気にしなくて大丈夫」に基づく）。
- 既存の検索機能（品名の部分一致・状態の完全一致）と一覧表示順をそのまま再利用し、CSV専用の検索条件や並べ替えは追加しない。
- JavaScript を使わずに実現する（プロジェクトの方針）。ボタンは通常のリンク・フォーム送信で現在の検索条件を引き継ぐ。
- 社員一覧・貸出履歴画面のCSV出力、CSVインポート、出力列の選択機能はスコープ外とする。
- ダウンロード操作自体の履歴（誰がいつ出力したか）の記録はスコープ外とする（要件定義書で監査ログがスコープ外のため）。
